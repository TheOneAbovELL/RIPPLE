# WS-11 handover: MCP server
Status: **Locally verified** (offline; production wiring needs Postgres, unverified) ·
2026-10-25 · ADR-0080 to ADR-0082

## What was built
- `src/ripple/mcp_server/`
  - `server.py` — `build_server(services, retriever, token_source)` → the SDK's
    low-level `mcp.server.Server` with seven tools from one `SPECS` table; `tools/list`
    publishes Pydantic-generated input schemas (`additionalProperties: false`) and
    output schemas; `tools/call` = validate into the input model → run → structured
    result; anticipated failures are `is_error` results `{"error": code, "detail"}`.
  - `schemas.py` — `SearchIn/SaveIn/UpdateIn/ForgetIn/ExplainIn/QuestionsIn/AnswerIn`
    (`extra="forbid"`, aware `valid_to`, correction needs content) and the outputs
    `SearchOut`, `WriteOut`, `ForgetOut`, `ExplainOut`, `QuestionsOut`, `AnswerOut`,
    `ErrorOut`.
  - `identity.py` — `resolve_user` (ADR-0040 hashing), `TokenSource` per transport
    (`env_token_source` for stdio via `RIPPLE_MCP_TOKEN`, `header_token_source` for
    HTTP), `BearerIdentity` server middleware binding the user to a contextvar per
    request and refusing `tools/call` without one, `current_user()`.
  - `tools.py` — `RippleTools`: search (Retriever + `visible_for_retrieval` again at
    the boundary + user check), save (`Intake.ingest`, origin and created_by `agent`,
    returns the questions that write parked), update (`Intake.edit` under ADR-0042:
    RETIRED → not_found, PENDING_USER → conflict), forget (`core.forget`), explain
    (why via the inspector's rule, version chain, events with decisions and questions,
    `visibility` visible|flagged|hidden), questions, answer. `_owned` answers
    `not_found` for unknown and foreign ids alike. LLM failures carry the user's open
    ChangeEvent ids.
  - `http.py` — `streamable_http_app`: SDK Starlette app (stateless, JSON responses)
    behind `BearerGate` (401 + `WWW-Authenticate: Bearer`).
  - `wiring.py` — `McpSettings.from_env` (`RIPPLE_MCP_TRANSPORT|HOST|PORT|PATH`),
    `production_services(env)` = `ripple.api.wiring.build_services` + `HybridRetriever`
    over `PostgresSearchBackend`.
  - `__main__.py` — `python -m ripple.mcp_server [--transport stdio|http] [--host]
    [--port] [--path]`; stdio refuses to start without `RIPPLE_MCP_TOKEN`.
- `tests/mcp_server/` — `harness.py` (InMemoryStore, FakeClock, RuleLinker, scripted
  detector/engine/resolver, InMemoryUserStore, real `HybridRetriever` over
  `InMemorySearchBackend` with the Intake indexing into it, in-process `mcp.Client`,
  `TokenHolder` token source); one file per tool; `test_auth.py`; `test_schemas.py`;
  `test_invariants_mcp.py` (I1 with the real and a deliberately leaky retriever, I4
  with `LLMChangeDetector` over `FakeLLM`, I7); `test_http.py` (401 gate, and a full
  client round trip over httpx2's ASGITransport with the app lifespan entered by hand);
  `test_main.py` (settings, transport choice, token requirement; builders injected).
- Docs: ADR-0080 (server shape and tool contract), ADR-0081 (identity), ADR-0082
  (transports and wiring); `docs/learning/mcp.md`.

## Tool surface
| Tool | Input | Returns |
|---|---|---|
| ripple_search | query, k ≤ 50, include_flagged | visible hits: memory, flagged, score, via, evidence |
| ripple_save | content, kind ∈ fact\|derived\|criteria, structured?, source_ref? | memory, change_kind, links_written, event_id, pending_questions |
| ripple_update | memory_id, content, structured?, valid_to? | same receipt; conflict on PENDING_USER |
| ripple_forget | memory_id | root_memory_id, deleted_ids, event_id, created_at |
| ripple_explain | memory_id | memory, status, visibility, why, history, events (decisions with reason and question) |
| ripple_questions | — | pending questions with memory, question, reason, event_id |
| ripple_answer | memory_id, reply, content?, structured?, valid_to? | memory_id, status, memory (None if RETIRED), event_id |
Error codes: `not_found`, `conflict`, `invalid_arguments`, `llm_output_invalid`,
`llm_unavailable` (both with `open_change_event_ids`), `internal_error` (no message).
No identity on `tools/call` → JSON-RPC `INVALID_REQUEST` "unauthorized"; HTTP → 401.

## Contract change requests (coordinator)
1. **`Services.retriever`** (ripple.api.services / wiring): the MCP server needs a
   `Retriever`; `build_services` keeps its engine private, so `production_services`
   opens a second engine on the same `DATABASE_URL` for `PostgresSearchBackend`. Add a
   `retriever: Retriever` field built once in `build_services` (the Conversation agent
   needs the same) and `production_services` collapses to one call.
2. **Lift `_why` and `_mentions`** out of `ripple.api.routers.memories` into a public
   module (e.g. `ripple.api.inspector` or core) — `ripple.mcp_server.tools` imports the
   private names today so ADR-0042's rule is stated once.
3. **Deployment (WS-0)**: an `mcp` service in the prod compose (`python -m
   ripple.mcp_server --transport http --host 0.0.0.0`) and a Caddy route for `/mcp`;
   `RIPPLE_MCP_*` variables in `.env.example`; ADR index entries for 0080–0082;
   CLAUDE.md command line `python -m ripple.mcp_server`.
4. `graphify update .` was not run from this session (shared graph, concurrent
   sessions); please rebuild at the checkpoint.

## Open problems
- Stateless HTTP means no elicitation/sampling; fine for these tools (ADR-0082).
- `ripple_update` cannot clear `valid_to` (omitted keeps the old value); add an
  explicit flag if a client needs it.
- `tests/mcp_server/test_http.py` imports `httpx2`, a transitive dependency of `mcp`
  (the SDK's client transport is built on it, not on `httpx`); if the coordinator
  prefers only declared dependencies in tests, pin `httpx2` in the dev group.

  it was repaired by its owner, nothing was changed here.
