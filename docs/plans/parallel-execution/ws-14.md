# WS-14 handover: link-finder data and evaluation harness
Status: Locally verified · Date: 2026-10-31 · Owner session: WS-14 (wave B)

## Summary
`training/` is a new package. It turns RippleBench v0 into C5 link pairs using a static
replay that is checked against all 35 scenarios. It also proves the split does not
leak, gives the author a blind 300-pair hand-check protocol, and scores any `Linker`
into results/. The training loop is an interface only ([human], strict xfails).

Two reviews ran: the code-reviewer (0 blockers, 6 majors, 12 minors) and the
eval-auditor (checklist below). All majors and minors were fixed except the items
listed under "Open problems".

## Eval-auditor checklist (docs/04), as applied
1. **Leakage: pass after fixes.**
   - The split by persona and template works for pairs that span templates.
   - Decontamination drops unordered text pairs; the named test now compares unordered texts.
   - Memory ids in the LLM prompt are now opaque ("m1"/"m2", assigned by a seeded coin).
   - Remaining near-duplicates are counted in the manifest rather than removed: `test_pairs_sharing_a_text_with_train`, `test_duplicate_texts`, `same_texts_different_labels` (= 0).
   - The harness reports the strict `held_out=both` cell separately.
2. **Baseline fairness: pass with open items.**
   - All linkers get the same single call per pair. Abstentions are counted the same way for every linker. Typed metrics are null for the rule linker, which only predicts one type.
   - Link types missing from train are flagged per type (`seen_in_train`; criteria_from has none in train).
   - The FakeLLM run is marked `plumbing_only` in config, metrics and the report.
   - Open: the orientation choice, the LLM's per-pair cost, and the threshold policy (see Open problems).
3. **Metric definitions: pass after fixes.**
   - Null precision and F1 in strata with no gold negatives.
   - Recall only per gold type.
   - False-positive rate per negative kind.
   - The rule for when F1 is 0 versus null is written in ADR-0093.
4. **Traceability (I8): pass after fixes.**
   - The ADRs and learning doc cite manifest keys instead of quoting counts.
   - Every process counter is written, including zeros.
   - config.json now has `models` and `prompt_versions` (as mappings), `seeds`, `data` (pair file and manifest sha, generator, pair seed, ratio, source and test personas/templates); metrics have `llm_calls`.
   - Every existing run says `git_sha: uncommitted`, so all numbers are TBD (pending a committed run).
5. **H3 risks (open):**
   - The strict cell is small on v0, so v0 cannot settle H3.
   - LLM usage, cost and model fallback are not visible to the harness.
   - Three seeds are not yet run.

## Open problems
- **v0 is small and regular.**
  - The train split holds a few dozen positives (counts in the manifest).
  - Every RULE positive is also a scenario link (`positives_rule_only` = 0).
  - Real training data needs v1 and LLM-labelled pairs (proposal 0002).
- **Decontamination removes exact text pairs only.** About half the test pairs share one text with train (`test_pairs_sharing_a_text_with_train`). The H3 reading must use `held_out=both`, and it needs confidence intervals over personas, which are not built.
- **H3 protocol gaps** (ADR-0093 consequences):
  - The LLM's cost per pair under one-candidate calls overstates its write-time cost. A candidate-set track is needed.
  - Run both `--new` orientations.
  - Fix the trained threshold on a validation persona.
  - Run three seeds.
- **Hand check:**
  - One labeller gives silver-versus-human agreement only.
  - The memory text still reveals the template family.
- **training_examples** trusts the `split` field. It does not re-run `leakage_problems` against the source manifest, because the generator and the named test already do.
- **[human]:** `train`, `TrainedLinker.load` and `TrainedLinker.propose` (roadmap Phase 4). These need the PyTorch/transformers dependency ADR first.
