## Requests to the coordinator (API and backend; WS-20 did not edit them)
1. **GET /vocabulary**: publish `profile_subject` ("student") and `profile_attributes`
   with a value type (number, text, bool) and whether each is permanent. The dashboard
   carries `PROFILE_SUBJECT` and `PROFILE_FACTS` as a stopgap in
   apps/web/src/features/domain/vocabulary.ts; remove them once published.
2. **GET /events?limit=N** (the user's ChangeEvents, newest first, I1-safe labels or
   memory ids only). Home reads `GET /me/export` today, which ships all history, the
   resume text and feedback to label five events.
3. **`OpeningView.deadline_value`** (src/ripple/domains/jobs/schemas.py `parse_deadline`)
   raises InvalidObjectError on a non-ISO deadline, although vocabulary.py says
   consumers treat it as unknown (ADR-0035). A deadline updated to "to be announced"
   would crash the reminder rule mid-ripple instead of declining.
4. **Blocker for every model call, even with a key**: `AnthropicClient.complete`
   (src/ripple/llm/providers/anthropic.py, kwargs at ~line 65) passes `temperature`,
   and anthropic==1.15.0 raises `TypeError: AsyncMessages.create() got an unexpected
   keyword argument 'temperature'`. Seen live: `POST /openings` → 503
   `LLMUnavailableError`. This environment has ANTHROPIC_API_KEY set, so resume and JD
   parsing, free-text statements and the LLM fallback all fail here today.
5. `POST /statements` with a structured fact can still answer 503 after writing the new
   version, when a rule declines and the LLM fallback fails (event left open). Consider
   201 with the open event id instead; the UI already warns "may already be saved".
6. `job_context_from_env`: accept `transport=` and `delivery_log=` so run_once can
   delegate instead of mirroring the wiring.
7. `OpeningAlreadyRecordedError` (InvalidObjectError) has no status mapping in
   src/ripple/api/errors.py, so a duplicate opening would surface as 500.
8. ADR index lines for 0130–0134; DEVLOG line; CLAUDE.md "Commands": add
   `uv run python -m tools.local_run [--seed-demo]` and
   `uv run python -m ripple.worker.run_once <job>`.
9. `graphify update .` was not run by WS-20 (several sessions write graphify-out
   concurrently); run it once at integration.
