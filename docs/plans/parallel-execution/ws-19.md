# WS-19 handover: trained link finder (ADR-0009) and the link-finder report
Status: Locally verified · Date: 2026-10-31 · Owner session: WS-19

## Summary
The [human] training loop is implemented at the author's request (2026-10-31).
ModernBERT-base is fine-tuned on CPU as a pair classifier over the jobs label space
(ADR-0125, ADR-0126). The result is served by `ripple.linking.trained.TrainedLinker`
behind the `Linker` protocol (created_by MODEL), and a `RIPPLE_LINKER` switch can select
it; the default stays the LLM linker (ADR-0128). The harness gained a transfer mode for
H4, CPU cost per call and a seed summary (ADR-0127). Three seeds were trained and scored
on the jobs test split and the finance transfer. The report is
docs/results/link-finder.md.

Results in one line each (all from an uncommitted tree, not citable until re-run):
- **jobs, held_out=both (primary):** trained F1 is above the rule linker on average but
  within seed noise. There is no evidence of a difference.
- **jobs, unseen personas:** trained is far above the rules, which is mostly template
  wording.
- **finance transfer (H4):** near-total failure (0, 1 and 3 predicted links across the
  seeds), far below the rule linker. H4 is not supported on this evidence.
- **H3:** pending the key (exact commands are in the report, section 5).

Reviews:
- **code-reviewer:** 0 blockers, 3 majors, 12 minors. All are fixed except the DEVLOG
  line, which is the coordinator's file (requested below).
- **eval-auditor:** found no copying errors, plus 1 blocker (the decontamination wording;
  198 of 392 test pairs share one text with train), 5 majors and 5 minors. All are fixed
  in the report.
