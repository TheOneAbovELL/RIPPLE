# WS-18 handover: metric functions and the full benchmark
Status: Locally verified (all owned paths green; paper macros still refuse, see requests)

## Summary
- **Metric bodies** (bench/metrics.py, ADR-0063 definitions): every function is
  implemented to its docstring. The 10 strict-xfail worked examples now pass, with the
  markers removed, and edge-case tests are added. New helpers keep one rule per idea:
  `stale_ids_at`, `stale_hits`, `questions_needed`, `scenario_metrics`, and
  `suite_metrics` (pooled counts, ADR-0120).
- **Retrieval probe** (bench/probe.py): after every gold event, the real `HybridRetriever`
  (lexical, graph expansion, flags kept, every match) is queried once per gold alias with
  its first content. The results live in the trace and feed the stale retrieval rate.
- **bench.run**:
  - `memory_metrics` is an object with all ten `paper.registry.MEMORY_METRICS` keys;
    `tokens_per_ripple` and `usd_per_ripple` are null without an LLM. Beside it:
    `memory_totals`, per-scenario `memory`, and `dependent_update_accuracy`.
  - `llm_calls` is summed from the resolvers' own `llm_calls`. The scripted oracle
    reports 0, and `llm_calls_note` says resolver_calls is what an LLM would have been
    called.
  - config.json gains `ablation`, `linker: "scenario"` with `linker_details`, and
    `retrieval_probe`; `models` and `prompt_versions` are `{}` instead of null.
  - `--ablation no_graph|no_ask_user` (ADR-0122) and `--generator-seeds N` (ADR-0121).
  - `source_sha256` covers exactly the files a run executes (a test enforces it).
- **Seeds** (bench/seeds.py, ADR-0121): generator seeds DEFAULT_SEED + 0..2, regenerated in
  memory, one folder per seed. The default seed must reproduce the checked-in hash, and
  the checked-in data is untouched. `data` is identical across a seed group;
  `seeds = {kind: generator, generator_seed, run_seed: null, data_sha256}`.
- **Grid and summary**: `bench/matrix.py` runs the 30 invocations (82 run folders).
  `bench/summary.py` writes results/<date>_benchsummary_<sha>/ (metrics.json and
  report.md) with seed means, ranges, counts, and the H1 and H2 readings. It uses only
  runs of the current code, refuses disagreeing reruns, mismatched configurations and
  mismatched seed sets, and leaves out incomplete runs.
- **Report** docs/results/benchmark.md answers H1 and H2 on these synthetic, oracle
  benchmarks with every number cited, and passes `paper.i8`. Short version:
  - H1: the accuracy half is met but by construction (ratio ≥ 1 under the oracle; the
    excess is ADR-0104's ask-family convention). The cost half is **not met**: ripple
    uses 45.3% of check_everything's resolver calls on v0 test, against the docs/04
    target of under one fifth, on small stores (results/2026-10-31_benchsummary_uncommitted).
  - H2: yes in direction (append_only 33.1% unflagged stale results on v0 test, ripple
    none; results/2026-10-31_benchsummary_uncommitted); no numeric target for "far
    below" exists yet.
- **Bug found and fixed during the work**: with a top-k cut, the probe's counts depended
  on tie order between versions with random uuid ids, so two grid runs disagreed on
  smoke. The probe now returns every match. A test proves the counts are stable: it
  fails 3 of 3 times with the old k = 3. A second full grid run into a scratch folder
  matched all 82 runs exactly.

Not touched: paper/**, training/**, src/**, apps/**, coordinator docs, tests/scenarios/*.yaml,
tests/bench_v1. Nothing committed.
