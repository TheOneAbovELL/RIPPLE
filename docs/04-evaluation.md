# Evaluation

## Questions
- Q1 Does Ripple keep memory correct after changes? (memory level)
- Q2 Does it stop agents acting on stale knowledge? (action level)
- Q3 At what cost, compared with re-checking everything?
- Q4 Can a small model infer links, and does it transfer to unseen domains?

## RippleBench
- Jobs track: simulated students over one placement season; events labelled with the
  exact expected state of every memory.
- News track: real stories that developed or were corrected; labelled downstream summaries.
  v1 (bench/data/news_v1) is generated and synthetic until the author curates real
  stories (ADR-0101; recipe in docs/learning/bench-v1.md); results from it carry that caveat.
- Finance track (test only): theses whose assumptions break. v1 scenarios and test-only
  C5 link pairs for H4 exist (ADR-0102), synthetic like the news track.
- External: STALE, for comparability. Read from a local copy only (ADR-0103); the mapping
  question below stays open until the author has the dataset.
- Link pairs (C5, bench/linkpairs.py): RippleBench scenarios turned into labelled
  parent/dependent pairs with provenance (rule, scenario, llm, human) for the link
  finder (ADR-0090..0094); evaluation is stratified by provenance and held-out cell.
Generated by scripts in bench/; every item has a stable id; train/test split by persona
and template, never by item.

## Baselines
Append-only · Newest-wins · Mem0-style · Check-everything (LLM re-checks all memories).

## Ablations
Without graph · LLM linker instead of trained · without Curator · without evidence
retrieval · without ask-user.

## Metrics
- Memory: correct updates/retirements, stale kept, wrongful deletions, questions asked
  (and needed?)
- Retrieval: stale retrieval rate
- Agent: task success, stale recommendations, time-to-consistency and the stale-action
  window (ADR-0062: events and days a wrong belief survives; events during which a
  stale recommendation was shown)
- Efficiency: LLM calls, tokens, cost, latency per ripple

## Hypotheses (initial targets; revised after Phase 3 baselines, with an ADR)
- H1 ≥90% of check-everything accuracy at <20% of its cost.
- H2 Stale retrieval rate far below standard memory retrieval.
- H3 Trained linker within 5 points of LLM linker at a fraction of the cost.
- H4 Linker transfers to finance with a modest drop.

Open until the Phase 3 baseline ADR: the single named metric "accuracy" in H1 refers
to; numeric targets for "far below" (H2) and "modest drop" (H4); whether the Mem0-style
baseline is the real library (then a dependency ADR) or a documented reimplementation;
whether STALE's scenario format maps onto a memory API without adaptation.
Also open, with provisional readings recorded in ADR-0110 point 8 (each a registry edit
in paper/registry.py, never a typed number): H1 "cost" read as resolver calls per ripple
with tokens and USD beside it; H2's comparator read as append-only; H3 and H4 read as
untyped F1 differences on silver labels with typed F1, the strict split and hand-check
agreement beside them; which linker the main ripple runs use; whether "three seeds"
means run seeds or generator seeds. No LLM judge exists yet, so the calibration step in
the protocol below has nothing to calibrate. Time-to-consistency is adopted (ADR-0062). ADR-0063 proposes reading H1's "accuracy"
as correct_updates over should-change targets; that reading is the collaborator's
proposal until the Phase 3 baseline ADR fixes the numbers.

## Protocol
- Runs write results/<YYYY-MM-DD>_<suite>_<shortsha>/ containing config.json
  (models, prompt versions, seeds), metrics.json and report.md.
- Model versions pinned per run. Three seeds minimum for headline numbers.
- LLM judge calibrated on a human-labelled sample; report agreement and both scores.
- Run the eval-auditor subagent before any number is published.

## Pilot metrics
Definitions, data sources and what is still TBD: docs/pilot/metrics.md (ADR-0106).
Saved or applied share of recommendations; days earlier than self-discovery; stale
recommendation rate; question usefulness; self-reported trust.
